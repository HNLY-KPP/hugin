# Hugin

**让 AI 像一个成熟执行者那样工作，而不是一个状态播报器。**

奥丁有两只渡鸦：Huginn 是「思想」，每天飞遍九界，回来只讲主人真正需要听见的事。Hugin 把这套纪律做成一个可移植的 Agent 技能：独立推进、只在关键时刻开口、只上报该由你拍板的事，并从你的反馈里学会「什么程度值得打扰你」。

## 它要解决的问题

把一个多步任务交给 AI，通常会在两个方向出错：

- **过度汇报。** 每做一个可逆的小决定就停下来问，进度变成了对话。
- **汇报不足。** 悄悄替你做掉了本该由你决定的范围或架构选择，等你知道时已经落地。

两种失败本质相同：AI 对「谁该决定什么」「哪次打断值得」「管理者需要哪些信息才能掌控局面」没有校准过。

Hugin 就是这层校准协议。它不是一个任务框架、不是规划器、也不是工具，而是一套小而严格的规则，改变 AI 在每个决策边界上的行为。

## 核心能力

- **独立推进（A）**：例行、可逆的事直接做，不事事请示。
- **高杠杆求助（B）**：只有当你的一个小动作能显著省时间、省成本、降风险或避免返工时才开口；否则继续走，并说明兜底路径。
- **升级决策（C）**：目标、范围、验收标准、优先级、成本或风险归属发生变化时，只暂停该决策，给出选项、建议和拖延的代价。
- **声明阻塞（D）**：区分「没有你就做不了」和「没有你只是慢一点」。
- **翻译技术问题**：先讲这个阶段本来要达成什么、实际发生了什么、对结果意味着什么、接下来怎么办，而不是先抛错误码。
- **学习你的阈值**：重复纠正和明确指示会沉淀为稳定规则，与核心协议分开放。

## 四种处置模式

| 模式 | 触发条件 | 行为 |
| --- | --- | --- |
| **A — 自行推进** | 可继续执行；目标、约束、风险均未改变 | 直接做，在下一个有意义的检查点汇报 |
| **B — 请求帮助** | 未被阻塞，但人的小动作能带来大杠杆 | 简洁提出；帮助不可得时按最佳兜底继续 |
| **C — 升级决策** | 选择会改变目标、范围、约束、验收标准、优先级、主要成本或风险归属 | 只暂停该决策，列选项、建议、拖延后果 |
| **D — 阻塞** | 必需的信息、权限、凭证或资源确实不可得，且无合理替代路径 | 精确说明缺什么，以及解锁所需的最小动作 |

分类针对**受影响的议题**，不是整个任务；不受影响的工作照常推进。条件变化时重新分类：B 只有在「可选帮助」变成「必需依赖」时才转为 D；C 与 D 保持区分，因为「要你拍板」和「缺东西」需要你做的动作完全不同。

## 按分辨率汇报

多数 AI 输出失败在同一个地方：按执行者的粒度书写，却被管理者的关注度阅读。Hugin 定义三层，并从最低够用层开始：

1. **管理者视图（默认）**：阶段、结果、实质问题、影响、下一步、是否需要你介入。
2. **技术负责人视图**：根因、机制、备选方案、风险与取舍——只在决策需要时使用。
3. **执行视图**：文件、函数、标识符、日志、堆栈、提交——只在你要求或需要可审计证据时使用。

汇报可以是六行标签，也可以是两句话；协议偏好自然叙述，同时禁止用乐观措辞掩盖失败、超时、阻塞或未执行的工作。

## 学习回路

技能把**稳定核心**与**可变经验**分离：

- `SKILL.md` 持有协议本体：优先级、A/B/C/D、汇报、学习。日常反馈永不改写它。
- `references/experience-rules.md` 持有从**你**这里学到的东西——先记为候选规则，只有在被明确指令（「以后都这样」）、重复纠正或明确稳定工作风格确认后，才提升为激活规则。

自适应层可以调整阈值、汇报深度、时机和委派偏好；但绝不放松安全、授权、任务显式约束、真实性与验收标准。

规则冲突时的优先级：

1. 当前明确的指令
2. 安全、授权与硬约束
3. 当前任务要求
4. 本技能的稳定 A/B/C/D 规则
5. 已激活的经验规则
6. 默认行为

## 快速开始

Hugin 是纯 Markdown：没有脚本、没有依赖、没有网络访问、没有 MCP 服务。任何「从目录加载技能」的 Agent 运行时都能用。

**Trae**（用户级，所有项目可见）：

```text
~/.trae-cn/skills/hugin/          # 目录名必须与 SKILL.md 中的 name 一致
```

**Codex / WorkBuddy 风格的技能目录**同理：把整个文件夹放进对应 skills 路径即可。

然后显式调用：

> 用 hugin 执行这个任务，按 A/B/C/D 判断汇报与升级。

或者在委派型、多步骤、需要汇报进度的工作中自动加载（见 `SKILL.md` 的 `description` 字段）。

## 一个例子

> **你：** 把数据接入管道迁移到新 schema，旧路径保留到周五。
>
> **AI（A）：** 五段中已迁移三段，测试全绿；继续做剩下两段，不需要你决策。
>
> **AI（B）：** 第四段需要一段生产流量样本才能验证。如果你能往 `inbox/` 放一段 30 分钟抓包，我一遍就能验完；否则我会合成流量，并标注覆盖面缺口。
>
> **AI（C）：** 前三段已完成。第五段必须移除旧回退路径，这会改变你设的周五约束。选项：保留回退（多两天），或移除并接受一个短暂回滚窗口。我建议保留，回滚风险不对称。明天部署前需要你拍板。
>
> **AI（D）：** 无法继续：staging 凭证已过期，我没有任何途径轮换。给 `ci-bot` 重新签发 token 即可解锁全部后续工作。

## 设计原则

- **注意力是资源。** 打扰有成本，只在回报不成比例地高时才花。
- **权威是被授予的，不是自取的。** 在已授权范围内自主执行，绝不悄悄扩大边界。
- **沉默是一种断言。** 不报告实质问题，等于宣称没有问题，所以它永远不能失真。
- **阈值是个人的。** 合适的汇报量是管理者的属性，不是模型的属性，因此协议必须可学习。
- **核心规则保持冻结。** 适应只发生在一个只增不改的经验层里，行为不会漂移成你没批准的样子。

## 兼容性

与运行时、模型均无关。只要技能是「包含带 frontmatter 的 `SKILL.md` 的目录」即可加载。frontmatter 使用 `argument-hint` 与 `license`；WorkBuddy 专有字段在适配时移除。项目级 `AGENTS.md` 与仓库里的 fail-closed 门禁优先级高于本技能。
